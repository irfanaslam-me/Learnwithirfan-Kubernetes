# Kubernetes Overview

## What is Kubernetes?

Kubernetes (also called K8s) is a tool that helps you run and manage your applications automatically.

Think of it like a **smart manager** for your apps:
- If your app crashes → Kubernetes restarts it automatically
- If too many users come → Kubernetes adds more copies of your app
- If you want to update your app → Kubernetes does it without any downtime

It was originally built by Google and is now used by companies all over the world.

---

## Why Do We Need Kubernetes?

Imagine you have a web app running inside Docker on one server.

**The problem without Kubernetes:**
```
Your app crashes at 3am.
→ You wake up.
→ You log in to the server.
→ You restart the app manually.
→ You go back to sleep.
```

**With Kubernetes:**
```
Your app crashes at 3am.
→ Kubernetes notices it immediately.
→ Kubernetes restarts it automatically.
→ You sleep peacefully.
```

## Kubernetes Architecture

A Kubernetes setup is called a **Cluster**. A cluster has two types of machines:

```
Kubernetes Cluster
│
├── Control Plane (the "brain")
│       Decides what to do
│
└── Worker Nodes (the "workers")
        Actually run your apps
```

### Control Plane — The Brain

| Part | What it does |
|------|--------------|
| API Server | The front door — all your `kubectl` commands go here |
| Scheduler | Decides which worker node should run your app |
| Controller Manager | Watches the cluster and fixes problems automatically |
| etcd | A database that stores the state of everything |

### Worker Node — The Worker

| Part | What it does |
|------|--------------|
| kubelet | Agent running on each node — runs your containers |
| kube-proxy | Handles network traffic to your apps |
| Container Runtime | Actually runs containers (Docker) |

## Kubernetes vs Docker

A very common question: *"I already use Docker — why do I need Kubernetes?"*

| Feature | Docker alone | Kubernetes |
|---------|-------------|------------|
| Run containers | ✅ | ✅ |
| Auto-restart on crash | ❌ | ✅ |
| Run on multiple machines | ❌ | ✅ |
| Auto-scale based on traffic | ❌ | ✅ |
| Zero-downtime deployments | ❌ | ✅ |

**Simple answer:** Docker runs one container on one machine. Kubernetes runs many containers across many machines — and manages them all for you.

## For Local Learning — Minikube

When learning Kubernetes, you don't need 10 servers. You use **Minikube**.

Minikube creates a fake mini Kubernetes cluster on your laptop using Docker.

```
Your Laptop
    └── Minikube (one Docker container pretending to be a full cluster)
            ├── Control Plane (brain)
            └── Worker Node (where your apps run)
```

It is perfect for learning and testing.
